## 6.2 实验设置总览

### 6.2.1 环境配置

**主对比环境**:ResourceCommons Medium 配置,详见第三章 3.9 节:

| 配置项 | 值 |
|---|---|
| $N$(agent 数) | 4 |
| $L$(网格大小) | 16×16 |
| $K$(资源点数) | 20 |
| $M$(hotspot 数) | 3 |
| $T_{\max}$(episode 长度) | 200 |
| 类型分配 $\rho_\tau$ | **2α + 2β**(agent 0,1 为 α;agent 2,3 为 β) |
| $c_t$ 演化模式 | 静态(模式 A),$c_0 \sim \mathcal{U}([0,1])$ |
| Fehr-Schmidt 参数 | $\kappa = 0.5$, $\lambda_{\text{disadv}} = 2.0$, $\lambda_{\text{adv}} = 0.6$ |
| 资源动力学 | $\alpha_{\min} = 0.02$, $\alpha_{\max} = 0.20$, $Q_{\max} = 10$ |
| 邻居因子 | $\kappa_f = 6.0$, $\theta_f = 0.3$, $d_{\text{nbr}} = 3$ |

**关键工程注意事项**:

- **类型与 ID 随机绑定**:为避免 agent_id ↔ type 绑定引入偏置,每个 seed 在 episode 开始时随机排列 (类型, agent_id) 对应关系。具体地,seed 0,2,4 用 (α, α, β, β) 绑定 (agent 0-3),seed 1,3 用 (β, β, α, α) 绑定 (agent 0-3),seed-类型轮换在 5 seeds 内确保每个 agent_id 至少跑过两种类型。
- **类型与 cap 独立采样**:类型 $\tau_i$ 与能力 $\text{cap}_i$ 独立采样,不存在类型偏向高/低能力的隐含相关。

### 6.2.2 Baseline 详细适配

本文与覆盖三大方法类的 6 个 baseline 进行对比,所有 baseline 必须公平适配到 ResourceCommons 环境(支持类型异质性 + 异构观测)。

| 类别 | Baseline | 出处 | 关键适配要点 |
|---|---|---|---|
| **Model-based** | MA-MuZero | AAAI 2024 [30] | 单一 PredictionNet 接收 (s, type_i) 作为输入 |
| | MAMBA | AAMAS 2022 [31] | Transformer-based world model,加入 type token |
| | MARIE | ICML 2024 [32] | 多智能体世界模型,加入 type embedding |
| **混合博弈专用** | Conflict-Aware GA | NeurIPS 2025 [13] | 原文是 actor-critic,需扩展支持类型异质 |
| **Model-free** | MAPPO | -- | 共享 critic + per-agent actor,加入 type 输入 |
| | QMIX | -- | Q-value 分解,加入 type 作为 conditioning |

**Baseline 适配协议**:

每个 baseline 必须实现以下两条最低公平性要求:

1. **类型可观测性匹配**:所有 baseline 与 Hyper-MuZero 一样采用 Self Info 设定(自己类型可见进入观测,他人类型不可见)。Baseline 的网络结构必须能接收 type_i 作为额外输入。
2. **独立 LR sweep**:每个 baseline 在 Easy 配置上独立做 LR sweep $\in \{1e-4, 3e-4, 1e-3, 3e-3, 1e-2\}$,3 seeds per LR,取最佳验证集 social welfare 的 LR。**Hyper-MuZero 也走同一 sweep 协议**,不存在"我方调好 / 对方未调"的不公平。

### 6.2.3 统计协议

- **主对比**:每 method 5 seeds,seeds = $\{0, 1, 2, 3, 4\}$;
- **消融**:每 variant 3-5 seeds(具体见各消融节);
- **指标报告**:均值 ± 标准差(across seeds);
- **显著性检验**:Welch's t-test(异方差),报告 $p$-value,显著阈值 $p < 0.05$。**所有声称"显著优于"的对比必须报告 $p$-value**;
- **训练步数**:Medium 配置 $T_{\max} = 1\text{M}$ 步,Easy 配置 $T_{\max} = 200\text{K}$ 步;
- **评估频率**:每 10K 步评估一次,每次评估 50 个 episode(across $c_0 \sim \mathcal{U}([0,1])$);
- **最终指标**:训练末期最后 50K 步的平均评估值(去除前期不稳定波动)。

### 6.2.4 算力规划

按当前协议,总实验规模如下:

| 实验 | Variant 数 | Seeds | Steps/run | 总 runs |
|---|---|---|---|---|
| LR sweep(全 baseline,Easy) | 7 × 5 | 3 | 200K | 105 |
| 主对比(Medium) | 7 | 5 | 1M | 35 |
| 消融 1(架构骨架) | 4 | 3 | 1M | 12 |
| 消融 2(Context 通路) | 5 | 3 | 1M | 15 |
| 消融 3(类型异质性) | 6 | 5 | 1M | 30 |
| 消融 4(规划器 2×2) | 4 | 3 | 1M | 12 |
| 消融 5(FS 参数) | 9 | 3 | 500K | 27 |
| 零样本泛化 | 3 × 4 | 5 | 1M(训练)+ 测试 | 60 |
| 信念质量监控 | 包含在主对比内 | -- | -- | 0 |
| **总计** | | | | **~296 runs** |

每个 Medium 1M-step run 估算 6 GPU 小时(A100),总算力需求约 **1800 GPU 小时**。

> **失败处理预案 - 算力不足**:若总算力 < 1500 GPU 小时,优先级如下:必保 = 主对比 + 消融 1 + 消融 3 + 零样本泛化(贡献 2 三断言的硬验证 + 主结果);可降级 = 消融 2/4/5(各只跑 3 seeds 即可);可砍 = 消融 5(留作 supplementary)。

### 6.2.5 μP 学习率对齐协议

按 Chapter 1.5 节贡献 4 加固协议 C,所有 baseline 全面启用 μP:

**步骤 1**:在代码中引入 mup 库(GitHub: microsoft/mup),为每个网络配置 base_shape;

**步骤 2**:LR sweep 在 base_shape 下进行,得到 base LR;

**步骤 3**:scaling 到 Medium 配置的 hidden_dim 时,μP 自动调整 LR;

**步骤 4**:主对比报告同时给出 base LR(LR sweep 结果)与 Medium 配置实际 LR(μP scaling 后的值)。

### 6.3.1 实验设置

**配置**:Medium 配置(N=4, 2α+2β),$c_0 \sim \mathcal{U}([0,1])$,$T_{\max} = 1\text{M}$ 步,5 seeds per method。

### 6.3.2 评估指标

按第三章 3.8.3 节定义:

| 指标 | 主指标? | 含义 |
|---|---|---|

### 6.3.3 c 值分段评估

由于 $c_0$ 在 $\mathcal{U}([0,1])$ 内随机,我们额外按 $c_0$ 分段评估,展示算法在不同博弈区段的相对优势:

| $c_0$ 区段 | 博弈语义 | 关键观察 |
|---|---|---|
| $[0.0, 0.3]$ | 荒年(纯竞争 + 类型 β 激进追赶) | 公地悲剧 + Fehr-Schmidt 损失 |
| $[0.3, 0.7]$ | 中间(本文核心优势区段) | 混合动机最复杂 |
| $[0.7, 1.0]$ | 丰年(资源充裕 + 类型 β 协同合作) | 合作易达成 |

**图 6.3**:7 个方法在三个 $c$ 区段下的社会物理福利对比(grouped bar chart)。

### 6.3.4 预期结果与论证逻辑

**预期主结果**:Hyper-MuZero > MA-MuZero ≈ MARIE > MAMBA > Conflict-Aware GA > MAPPO > QMIX,社会物理福利相对 MA-MuZero 提升 15-30%,可持续性显著更高。

**论证逻辑**:

- Hyper vs MA-MuZero:核心差距来自双路超网络的类型异质解耦(断言 A 在主对比中的间接验证);
- Hyper vs MAMBA/MARIE:类型异质 + belief inference 的容量优势(断言 B 的间接证据);
- Model-based vs Model-free:样本效率差距,中间 $c$ 区段尤其明显;
- Conflict-Aware GA:其原始设计针对静态混合博弈,在动态 c 下适应力弱。

> **失败处理预案 - 主对比 Hyper-MuZero 优势 < 10%**:
> - **若仅在 Medium 上失败,Easy 上正常**:说明 Medium 容量瓶颈未达到,加大 hidden_dim 重跑;
> - **若 Easy + Medium 都失败**:贡献 2 整体降级,重新审视 hyper_rew 的实际表达能力。**触发条件**:Hyper vs MA-MuZero 物理福利差距 $< 5\%$ 且 $p > 0.1$。
> - **触发预案**:调整 Chapter 1.5 贡献 2 的语气,从"显著优势"降为"在特定区段有优势";同时把 Chapter 5 MVE+CRN 规划器作为补救主推贡献。

## 6.4 消融 1:架构骨架对比(断言 B 的硬验证)

### 6.4.1 实验设置

按 Chapter 1.5 节贡献 4 加固协议 B,四条 variant 全部启用 μP + 独立 LR sweep:

| Variant | 描述 | 参数对齐方式 |
|---|---|---|
| **Shared** | (s, a) → r/π/v,无 c_ctx/role/belief 输入 | 基线参考 |

### 6.4.4 论证逻辑

断言 B 的硬验证逻辑:

1. **Shared 基线 < Hyper**:证明 c_ctx/role/belief 输入有用(基础门槛);
2. **Input-Wide 与 Input-Deep 都 < Hyper**:证明优势不来自单纯网络容量而是来自 hypernetwork 的容量分配几何(Chapter 4.1.2 节论证的硬验证);

## 6.5 消融 2:Context 通路拆分(断言 C 的验证)

### 6.5.1 实验设置

| Variant | $c_{\text{ctx}}$ | $\text{role}_i$(含 type_emb + cap_emb + id_emb) | $\text{belief}_i$(含 $\hat{c}$ + $\hat{z}$) |
|---|---|---|---|
| **Full(本文)** | ✓ | ✓ | ✓ |
| **No belief** | ✓ | ✓ | ✗(belief_i 替换为零向量) |
| **No type** | ✓ | role 中 type_emb 替换为零(cap + id 保留),belief 中 $\hat{z}$ 替换为零 | -- |
| **No cap** | ✓ | role 中 cap_emb 替换为零(type + id 保留) | ✓ |
| **Only c** | ✓ | role_i 全替换为零 | belief_i 全替换为零 |

**注**:"替换为零"是为了保持网络输入维度不变,避免架构差异污染对比。

**配置**:Medium,3 seeds per variant,1M 步。

### 6.5.2 预期结果

按 Chapter 4.1.3 节三层 motivation 的设计预测:

- **No belief**:零样本泛化能力下降明显(辅层 1 验证);
- **No type**:类型异质场景(2α+2β)下主对比性能下降显著(辅层 1 + 主层验证,因为 type 同时影响 RewardHead 与 PredictionNet);
- **No cap**:个体福利方差(公平性)恶化,社会物理福利轻微下降(辅层 2 验证);
- **Only c**:近乎退化为单类型 MA-MuZero,所有指标显著恶化。

### 6.5.4 论证逻辑

断言 C 的验证:

1. **每个通路的去除都导致主指标显著下降** → 三通路缺一不可;
2. **三个通路的影响相互正交**:No belief, No type, No cap 的影响不应严重重叠(若 No belief 和 No type 完全等价,说明 belief 中的 $\hat{z}$ 与 type_emb 冗余);
3. **影响可累加**:Only c 的恶化幅度应大致等于 No belief + No type + No cap 三者之和。

> **失败处理预案 - 通路冗余**:
> - **若 No type 与 No belief 影响完全等价**:说明 $\hat{z}$ 直接编码了对手 type_emb(因为训练时是 Oracle 监督),冗余存在。**预案**:在消融 2 中加入 No-self-type 变体(自己 type_emb 移除但保留 belief 通路),证明 self type 与 belief 中 opp type 的独立价值;
> - **若 No belief 影响很小**:说明 BeliefNet 训练不充分,$\hat{z}$ 准确率低。**触发条件**:No belief 相对 Full 的差距 $< 3\%$。预案:检查 BeliefNet 课程学习,延长阶段 2,提高 $\hat{z}$ 准确率到 85%+ 再重跑。

## 6.6 消融 3:类型异质性扫描(断言 A 的硬验证,本章最关键实验)

### 6.6.1 实验设置

**这是本章最重要的单个实验,直接决定贡献 2 主层 motivation(类型梯度撕裂)的成立性**。

扫描类型 β 比例 $\rho_\beta \in \{0/4, 1/4, 2/4, 3/4, 4/4\}$ 五个数据点,加上 1α+3β 对照点(等价于 3/4 但 type-id 绑定不同),共 6 个数据点。每点 5 seeds。

**对比对象**:Hyper-MuZero(本文)vs MA-MuZero(共享 RewardHead 的强 baseline 代表)。

**Configurable variant**:在 Easy 配置上额外跑 N=2 的扫描(1α+1β vs 2α+0β vs 0α+2β),3 个数据点,3 seeds per point,9 runs。**用途**:验证"类型异质性放大 Hyper 优势"在不同 N 下的稳健性。

### 6.6.2 关键预期与可能的"非对称钟形"

**理想预期**:对称钟形曲线,峰值在 2α+2β 处:

```
        Hyper vs MA-MuZero 性能差距
            ▲
            |          ●  ← peak at 2/4
            |        ● | ●
            |      ●   |   ●
            |    ●     |     ●
            |  ●       |       ●
            |●         |         ●●
            └─────────────────────→  ρ_β
              0/4  1/4 2/4 3/4 4/4
```

**也可能出现的非对称钟形**(峰值偏向 α-多侧):

```
        Hyper vs MA-MuZero 性能差距
            ▲
```

### 6.6.3 1α+3β 额外对照的诊断价值

1α+3β 与 3α+1β 在数学上"类型异质度"相同(都是 3:1 不对称),但**类型 β 学习难度可能更高**(Fehr-Schmidt 项使训练目标更复杂)。对比:

- 若 1α+3β 与 3α+1β 性能差距相似 → 类型 β 学习难度对称,钟形曲线由"类型异质度"主导;
- 若 1α+3β 显著差于 3α+1β → 类型 β 学习难度更高,钟形曲线峰值偏向 α-多侧(非对称钟形)。

### 6.6.5 论证逻辑

断言 A 的硬验证:

1. **0/4 与 4/4(同质)处**:Hyper 与 MA-MuZero 差距应接近 0(理论上无类型梯度撕裂,无优势);
2. **中间比例**:Hyper 显著优于 MA-MuZero,差距随类型异质度增加而增加(直到峰值);
3. **峰值位置**:对称(2/4)或非对称(1/4 或 3/4),前者是理想,后者也是有效正向结果。

> **失败处理预案 - 断言 A 失败**:
> - **若 0/4 和 4/4 处 Hyper 显著优于 MA-MuZero**:说明优势不来自类型异质,而来自其他来源(如 belief 推断、cap 通路)。**预案**:断言 A 重新定位为"在类型异质下优势更大",而非"优势源于类型异质";同时检查消融 2 的 No type 变体,确认 type 通路贡献;
> - **若所有比例下 Hyper vs MA-MuZero 都无显著差距**:贡献 2 主层 motivation 整体失败,触发 Chapter 1.5 贡献 2 的降级方案;
> - **触发条件**:钟形曲线最大差距 $< 8\%$ 且 $p > 0.05$。
> - **决策点 checkpoint**:**这是本项目的核心生死判官实验**,建议在 Easy 配置(N=2 扫描)上先跑,3 周内有结果,决定是否继续 Medium 主对比;若 Easy 上钟形曲线峰值差距 $< 5\%$,**立即触发 P0 重新定位讨论**,不要等 Medium。

## 6.12 局限性与失败案例分析

### 6.12.1 已知局限性

诚实地列出本文方法的局限性,这是审稿人会盯的"reviewer 3 章节"。

**局限性 1**:类型机制需要 Oracle 监督。本文 BeliefNet 训练时假定 type_j 在训练阶段可获得(Oracle),测试阶段才不可见。这适用于"训练数据可标注"的场景(如仿真训练 → 真实部署),但不适用于完全无监督的设定。未来工作可探索完全自监督的类型推断。

**局限性 2**:类型数固定。本文限定为 2 种类型(α, β),未探索 3+ 种类型或连续类型空间。N 类型情况下,$\hat{z}$ 从 2 分类变为 N 分类,课程学习协议需要扩展。

**局限性 3**:类型在 episode 内固定。本文假设类型在 episode 内不变,这与现实"心理状态可能随情境变化"不完全对应。未来可探索类型也可演化的设定。

**局限性 4**:规模化验证有限。本文主对比仅 N=4,Hard 配置(N=8)只作为附录扩展实验。N=16+ 的规模化验证留待后续工作。

**局限性 5**:奖励通信。本文假定 agent 间不能通信,只能通过观察推断。未来可探索受限通信下的 BeliefNet 升级。

### 6.12.2 失败案例分析

报告训练中遇到的具体失败案例及其处理,展示方法的鲁棒性边界:

| 失败模式 | 出现频率 | 处理方式 |

| $\hat{z}$ 准确率波动 | 阶段 2 退火期 | 延长阶段 2 至 50% |
| 表示坍缩 ($s^k$ 方差 → 0) | 罕见 | $\lambda_{\text{cons}}$ 升至 1.0 |

本章对 Chapter 1.5 节四项贡献的 4 个可证伪断言进行了系统的实验验证:
